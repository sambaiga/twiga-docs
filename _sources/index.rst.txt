   <!-- ── Why Twiga ─────────────────────────────────────────── -->
   <div class="tw-why">
     <p class="tw-why-lead">
       Most forecasting libraries force a choice between ML and deep learning, between
       point forecasts and probabilistic ones, or between flexibility and production
       readiness. Twiga removes that trade-off.
     </p>

     <div class="tw-features">

       <details class="tw-feature">
         <summary class="tw-feature-summary">
           <span class="tw-feature-dot" style="background:linear-gradient(135deg,#0f718e,#069fac)">
             <i class="bi bi-arrow-left-right"></i>
           </span>
           <span class="tw-feature-title">One interface, every model</span>
           <span class="tw-feature-teaser">Single <code>TwigaForecaster</code> API for ML and neural networks  -  swap models by changing a config.</span>
           <i class="bi bi-chevron-down tw-feature-chevron"></i>
         </summary>
         <div class="tw-feature-body">
           <p>A single <code>TwigaForecaster</code> trains, tunes, evaluates, and backtests
           any model  -  Naive, Drift, CatBoost, LightGBM, RandomForest, NGBoost, MLPF, N-HiTS  -  through
           an identical API. Switching from a gradient-boosted tree to a neural network
           means changing one config object, not rewriting training code. The entire
           workflow  -  feature engineering, training, hyperparameter optimisation,
           backtesting, and calibration  -  is unified in a single interface with no
           library boundaries to cross.</p>
         </div>
       </details>

       <details class="tw-feature">
         <summary class="tw-feature-summary">
           <span class="tw-feature-dot" style="background:linear-gradient(135deg,#6a1b9a,#8e24aa)">
             <i class="bi bi-layers-fill"></i>
           </span>
           <span class="tw-feature-title">Composable probabilistic architecture</span>
           <span class="tw-feature-teaser">Mix any backbone (MLPF, MLPGAM, N-HiTS) with any distribution head  -  Normal, Gamma, QR, StudentT, and more.</span>
           <i class="bi bi-chevron-down tw-feature-chevron"></i>
         </summary>
         <div class="tw-feature-body">
           <p>Neural models follow a strict backbone/head contract: every architecture
           exposes an <code>encode()</code> method producing a latent vector consumed by
           interchangeable distribution heads  -  Normal, Laplace, LogNormal, Gamma, Beta,
           StudentT, QR, FPQR. Any backbone pairs with any head without modifying backbone
           code, giving you a full matrix of probabilistic models from a small set of
           building blocks. Because the backbone/head contract is explicit and enforced,
           adding a new architecture or a new distribution head is a focused, isolated
           change rather than a fork of an entire model class.</p>
         </div>
       </details>

       <details class="tw-feature">
         <summary class="tw-feature-summary">
           <span class="tw-feature-dot" style="background:linear-gradient(135deg,#2e7d32,#43a047)">
             <i class="bi bi-shield-check"></i>
           </span>
           <span class="tw-feature-title">Calibrated uncertainty on any model</span>
           <span class="tw-feature-teaser">Conformal prediction wraps any trained model  -  including plain LightGBM  -  with coverage-guaranteed intervals.</span>
           <i class="bi bi-chevron-down tw-feature-chevron"></i>
         </summary>
         <div class="tw-feature-body">
           <p>Conformal prediction (CQR and CRC) wraps <em>any</em> trained model  -
           including plain point-forecast ML models like LightGBM  -  with finite-sample,
           distribution-free prediction intervals that carry a formal coverage guarantee.
           One call after training, no retraining, no distributional assumptions required.
           This post-hoc calibration layer works across the entire model catalog, not just
           purpose-built probabilistic architectures.</p>
         </div>
       </details>

       <details class="tw-feature">
         <summary class="tw-feature-summary">
           <span class="tw-feature-dot" style="background:linear-gradient(135deg,#e65100,#fb8c00)">
             <i class="bi bi-sliders"></i>
           </span>
           <span class="tw-feature-title">Experiment-ready by default</span>
           <span class="tw-feature-teaser">Pydantic configs, built-in Optuna HPO, time-based CV, and checkpoint persistence  -  all first-class features.</span>
           <i class="bi bi-chevron-down tw-feature-chevron"></i>
         </summary>
         <div class="tw-feature-body">
           <p>Every component  -  data pipeline, model architecture, CV strategy, conformal
           calibration  -  is configured through validated Pydantic dataclasses that are
           serialisable, diffable, and directly wired to Optuna search spaces. Hyperparameter
           tuning with TPE sampler and Hyperband pruner, expanding/rolling window
           backtesting, and checkpoint-based resume are first-class features, not
           afterthoughts bolted on later.</p>
         </div>
       </details>

       <details class="tw-feature">
         <summary class="tw-feature-summary">
           <span class="tw-feature-dot" style="background:linear-gradient(135deg,#00695c,#00897b)">
             <i class="bi bi-graph-up-arrow"></i>
           </span>
           <span class="tw-feature-title">Statistical analysis &amp; feature intelligence</span>
           <span class="tw-feature-teaser">12 statistical modules, 8 association methods, and ensemble feature ranking  -  all in <code>twiga.core.stats</code> and <code>twiga.core.data</code>.</span>
           <i class="bi bi-chevron-down tw-feature-chevron"></i>
         </summary>
         <div class="tw-feature-body">
           <p>Before training a model, Twiga gives you a complete toolkit to understand
           your data. <code>AssociationAnalyzer</code> computes eight types of feature-target
           association in one call  -  Pearson, Spearman, Kendall, Xi-correlation, Predictive
           Power Score, Mutual Information, ANOVA F-score, and Chi-squared.
           <code>select_top_features</code> aggregates these signals with Borda-count rank
           fusion and RF importance to produce a robust, ensemble-ranked feature list.
           The <code>twiga.core.stats</code> toolkit adds stationarity tests (ADF, KPSS),
           ACF/PACF diagnostics, entropy measures (permutation, approximate, sample, DFA,
           Hurst), residual diagnostics (Cook's distance, leverage, standardised residuals),
           and optimal-lag selection  -  all returning tidy DataFrames ready for downstream
           use.</p>
         </div>
       </details>

       <details class="tw-feature">
         <summary class="tw-feature-summary">
           <span class="tw-feature-dot" style="background:linear-gradient(135deg,#00695c,#26a69a)">
             <i class="bi bi-gear-wide-connected"></i>
           </span>
           <span class="tw-feature-title">Production MLOps out of the box</span>
           <span class="tw-feature-teaser">MLflow tracking, versioned checkpoints, Evidently drift monitoring, FastAPI serving, and Prefect retraining  -  all first-class features, not afterthoughts.</span>
           <i class="bi bi-chevron-down tw-feature-chevron"></i>
         </summary>
         <div class="tw-feature-body">
           <p>Twiga ships a five-module MLOps stack installed with
           <code>pip install twiga[mlops]</code>.
           <code>TwigaTracker</code> wraps MLflow to log every training run  -  parameters,
           metrics, dataset lineage, and the full model artefact  -  as a reproducible PyFunc
           object. Versioned checkpoints (<code>on_save_checkpoint</code> /
           <code>on_load_checkpoint</code>) persist the model and its fitted data pipeline
           together with a monotonically versioned JSON manifest, giving a lightweight audit
           trail without an external artefact store. <code>ForecastMonitor</code> uses
           Evidently to detect feature distribution drift and track regression performance
           (MAE, RMSE, MAPE) as ground truth becomes available. <code>create_app()</code>
           returns a production-ready FastAPI service with <code>/predict</code>,
           <code>/predict-interval</code>, <code>/monitor/drift</code>,
           <code>/monitor/performance</code>, and <code>/reload</code> endpoints  -  all
           CPU-bound calls are offloaded via <code>anyio.to_thread.run_sync</code> so the
           event loop stays responsive under load. Finally, <code>retraining_flow()</code>
           automates the full drift-check → retrain → evaluate → promote → hot-reload cycle
           as a schedulable Prefect deployment.</p>
         </div>
       </details>

     </div>
