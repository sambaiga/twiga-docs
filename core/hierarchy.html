Hierarchical Alignment#

Source Files

  • twiga/hierarchy/structure.py - aggregate_panel, level_key

  • twiga/hierarchy/alignment.py - align_to_level, alignment_multipliers

A global model trained on thousands of products forecasts each one well, but errors it makes for every series at once (a missed trend, a level shift) add up when series are summed. On aggregated series (store, department, total) trend and level are far easier to see. Top-down alignment keeps the bottom model’s split across products and takes the level from a forecast made directly at a higher level:

\[ m_{g,t} = \frac{\hat{y}^{\text{level}}_{g,t}}{\sum_{i \in g} \hat{y}_{i,t}}, \qquad \tilde{y}_{i,t} = \hat{y}_{i,t}\,\bigl(1 + \lambda\,(m_{g,t} - 1)\bigr) \]

This is the adjustment the 2nd- and 5th-placed M5 Accuracy methods applied: N-BEATS forecasts at the top levels, or the recent store-department mean, as the reference. The damping \(\lambda\) (strength) plays the role of Anderer’s bias multiplier.

Workflow#

from twiga.core.config import DataPipelineConfig
from twiga.forecaster.core import TwigaForecaster
from twiga.hierarchy import aggregate_panel, align_to_level

# 1. Bottom-level forecasts from a global model (panel mode).
bottom_preds, _ = bottom_forecaster.backtesting(panel)

# 2. Aggregate exactly the forecasted series to a level and forecast that small panel.
forecasted = panel[panel["id"].isin(bottom_preds["id"].unique())]
level = aggregate_panel(forecasted, ["store_id", "dept_id"], ["sales"], id_column="id", key_column="series")
level_config = DataPipelineConfig(
    target_feature="sales", period="1MS", lookback_window_size=24, forecast_horizon=6, id_column="series"
)
level_preds, _ = TwigaForecaster(level_config, level_model, cv_config).backtesting(level)

# 3. Rescale the bottom forecasts so each store-department sums to its level forecast.
aligned = align_to_level(
    bottom_preds,
    level_preds[["series", "timestamp", "forecast", "Folds"]],
    ["store_id", "dept_id"],
    id_column="id",
    tags=tags,  # one row per id with store_id, dept_id
    group_columns=["Folds"],
)

Things to get right:

  • Same series on both sides. Aggregate only the series that have a bottom forecast. Series too short for a window, or launched later, would otherwise add to every level reference, and alignment would inflate the forecasted series to cover sales it never sees. When that set changes across backtest folds, build the level reference per fold.

  • One reference per group and timestamp. level_forecasts must hold a single forecast per level group and timestamp (and fold); filter to one model first.

  • Bounds. Multipliers are clipped to clip=(0.5, 2.0) by default to guard against near-zero bottom sums; strength < 1 damps the whole adjustment.

  • Intervals and quantiles. Pass interval bounds or quantile columns in scale_columns to rescale them with the same factor.

Evaluate the result across levels with hierarchical_scores() (see Panel Metrics).

API Reference#

Hierarchy structure: aggregate a long-format bottom-level panel to a level of the hierarchy.

twiga.hierarchy.structure.aggregate_panel(data, level_columns, value_columns, *, id_column, date_column='timestamp', tags=None, key_column='series', group_columns=())#

Sum a bottom-level panel to one level of the hierarchy.

The result is itself a long panel, one row per level group and timestamp, so any twiga model can forecast it (DataPipelineConfig(id_column=key_column)).

Parameters:

  • data (DataFrame) – Bottom-level long frame (history or forecasts).

  • level_columns (Sequence[str]) – Columns that define the level, e.g. ["store_id", "dept_id"]; empty for the grand total.

  • value_columns (Sequence[str]) – Summable columns to aggregate (sales, forecasts, revenue, …).

  • id_column (str) – Bottom-level series identifier.

  • date_column (str) – Timestamp column.

  • tags (DataFrame | None) – One row per bottom series with the hierarchy columns; only needed when data does not already carry the level columns.

  • key_column (str) – Name of the level-group key column in the result.

  • group_columns (Sequence[str]) – Extra columns kept separate while summing (e.g. Model, Folds).

Return type:

DataFrame

Returns:

[*group_columns, *level_columns, date_column, *value_columns, key_column].

twiga.hierarchy.structure.level_key(frame, level_columns)#

  • level_columns (Sequence[str]) – Columns that define the level; empty for the grand total.

Return type:

Top-down alignment of bottom-level forecasts to forecasts made at a higher level.

A global model trained on thousands of products forecasts each one well, but errors it makes for every series at once (a missed trend, a level shift) add up when series are summed. Trend and level are far easier to forecast on aggregated series. Alignment keeps the bottom model’s split across products and takes the level from the aggregate forecast:

multiplier[g, t] = level_forecast[g, t] / sum_{i in g} bottom_forecast[i, t] aligned[i, t] = bottom_forecast[i, t] * (1 + strength * (multiplier[g, t] - 1))

This is the adjustment the 2nd- and 5th-placed M5 Accuracy methods applied (N-BEATS forecasts at the top levels, or the recent store-department mean, as the reference). strength < 1 damps the adjustment, like Anderer’s bias multiplier.

twiga.hierarchy.alignment.align_to_level(bottom, level_forecasts, level_columns, *, id_column, date_column='timestamp', forecast_column='forecast', level_key_column='series', level_forecast_column='forecast', tags=None, group_columns=(), strength=1.0, clip=(0.5, 2.0), scale_columns=())#

Rescale bottom-level forecasts so each level group sums to its level forecast.

Each product keeps its share of the group; the group’s level (and so its trend) comes from the level forecast. Groups or timestamps without a level forecast are left unchanged.

The level forecasts must describe the same set of series as bottom: aggregate only the series that have a bottom forecast. Series without one (too short for a window, launched later) would otherwise add to every level reference, and alignment would inflate the forecasted series to cover sales it never sees.

Parameters:

  • bottom (DataFrame) – Bottom-level forecasts, e.g. the predictions frame from backtesting().

  • level_forecasts (DataFrame) – Forecasts of the aggregated series (see alignment_multipliers()).

  • level_columns (Sequence[str]) – Columns that define the level, e.g. ["store_id", "dept_id"].

  • id_column (str) – Bottom-level series identifier.

  • date_column (str) – Timestamp column.

  • forecast_column (str) – Bottom forecast column to align.

  • level_key_column (str) – Level-group key column in level_forecasts.

  • level_forecast_column (str) – Forecast column in level_forecasts.

  • tags (DataFrame | None) – Hierarchy columns per bottom id, when bottom lacks the level columns.

  • group_columns (Sequence[str]) – Columns matched between the frames besides key and timestamp (e.g. Folds).

  • strength (float) – 1 applies the full multiplier, 0 none; values in between damp the adjustment.

  • clip (tuple[float, float] | None) – Bounds on the multiplier. None disables.

  • scale_columns (Sequence[str]) – Further columns rescaled by the same factor (interval bounds, quantiles).

Return type:

DataFrame

Returns:

bottom with forecast_column (and scale_columns) aligned and an alignment column holding the factor applied to each row.

twiga.hierarchy.alignment.alignment_multipliers(bottom, level_forecasts, level_columns, *, id_column, date_column='timestamp', forecast_column='forecast', level_key_column='series', level_forecast_column='forecast', tags=None, group_columns=(), clip=(0.5, 2.0))#

Per level group and timestamp, the factor that makes bottom forecasts sum to the level forecast.

Parameters:

  • bottom (DataFrame) – Bottom-level forecasts (long frame).

  • level_forecasts (DataFrame) – Forecasts of the aggregated series, keyed by level_key_column (the key aggregate_panel() produces).

  • level_columns (Sequence[str]) – Columns that define the level.

  • id_column (str) – Bottom-level series identifier.

  • date_column (str) – Timestamp column (in both frames).

  • forecast_column (str) – Bottom forecast column.

  • level_key_column (str) – Level-group key column in level_forecasts.

  • level_forecast_column (str) – Forecast column in level_forecasts.

  • tags (DataFrame | None) – Hierarchy columns per bottom id, when bottom lacks the level columns.

  • group_columns (Sequence[str]) – Columns matched between the frames besides the key and timestamp (e.g. Folds); a bottom Model column is aligned per model automatically.

  • clip (tuple[float, float] | None) – Bounds on the multiplier; guards against a near-zero bottom sum. None disables.

Return type:

DataFrame

Returns:

[*group, key, date, bottom_sum, level_forecast, multiplier] per level group and timestamp.
