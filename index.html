Point & probabilistic time series forecasting -
one interface, every model.

Python 3.12 Apache 2.0 v0.1.0
Get Started Gallery
Install pip install twiga[pytorch,gbtree]

Most forecasting libraries force a choice between ML and deep learning, between point forecasts and probabilistic ones, or between flexibility and production readiness. Twiga removes that trade-off.

One interface, every model Single TwigaForecaster API for ML and neural networks - swap models by changing a config.

A single TwigaForecaster trains, tunes, evaluates, and backtests any model - Naive, Drift, CatBoost, LightGBM, RandomForest, NGBoost, MLPF, N-HiTS - through an identical API. Switching from a gradient-boosted tree to a neural network means changing one config object, not rewriting training code. The entire workflow - feature engineering, training, hyperparameter optimisation, backtesting, and calibration - is unified in a single interface with no library boundaries to cross.

Composable probabilistic architecture Mix any backbone (MLPF, MLPGAM, N-HiTS) with any distribution head - Normal, Gamma, QR, StudentT, and more.

Neural models follow a strict backbone/head contract: every architecture exposes an encode() method producing a latent vector consumed by interchangeable distribution heads - Normal, Laplace, LogNormal, Gamma, Beta, StudentT, QR, FPQR. Any backbone pairs with any head without modifying backbone code, giving you a full matrix of probabilistic models from a small set of building blocks. Because the backbone/head contract is explicit and enforced, adding a new architecture or a new distribution head is a focused, isolated change rather than a fork of an entire model class.

Calibrated uncertainty on any model Conformal prediction wraps any trained model - including plain LightGBM - with coverage-guaranteed intervals.

Conformal prediction (CQR and CRC) wraps any trained model - including plain point-forecast ML models like LightGBM - with finite-sample, distribution-free prediction intervals that carry a formal coverage guarantee. One call after training, no retraining, no distributional assumptions required. This post-hoc calibration layer works across the entire model catalog, not just purpose-built probabilistic architectures.

Experiment-ready by default Pydantic configs, built-in Optuna HPO, time-based CV, and checkpoint persistence - all first-class features.

Every component - data pipeline, model architecture, CV strategy, conformal calibration - is configured through validated Pydantic dataclasses that are serialisable, diffable, and directly wired to Optuna search spaces. Hyperparameter tuning with TPE sampler and Hyperband pruner, expanding/rolling window backtesting, and checkpoint-based resume are first-class features, not afterthoughts bolted on later.

Statistical analysis & feature intelligence 12 statistical modules, 8 association methods, and ensemble feature ranking - all in twiga.core.stats and twiga.core.data.

Before training a model, Twiga gives you a complete toolkit to understand your data. AssociationAnalyzer computes eight types of feature-target association in one call - Pearson, Spearman, Kendall, Xi-correlation, Predictive Power Score, Mutual Information, ANOVA F-score, and Chi-squared. select_top_features aggregates these signals with Borda-count rank fusion and RF importance to produce a robust, ensemble-ranked feature list. The twiga.core.stats toolkit adds stationarity tests (ADF, KPSS), ACF/PACF diagnostics, entropy measures (permutation, approximate, sample, DFA, Hurst), residual diagnostics (Cook's distance, leverage, standardised residuals), and optimal-lag selection - all returning tidy DataFrames ready for downstream use.

Production MLOps out of the box MLflow tracking, versioned checkpoints, Evidently drift monitoring, FastAPI serving, and Prefect retraining - all first-class features, not afterthoughts.

Twiga ships a five-module MLOps stack installed with pip install twiga[mlops]. TwigaTracker wraps MLflow to log every training run - parameters, metrics, dataset lineage, and the full model artefact - as a reproducible PyFunc object. Versioned checkpoints (on_save_checkpoint / on_load_checkpoint) persist the model and its fitted data pipeline together with a monotonically versioned JSON manifest, giving a lightweight audit trail without an external artefact store. ForecastMonitor uses Evidently to detect feature distribution drift and track regression performance (MAE, RMSE, MAPE) as ground truth becomes available. create_app() returns a production-ready FastAPI service with /predict, /predict-interval, /monitor/drift, /monitor/performance, and /reload endpoints - all CPU-bound calls are offloaded via anyio.to_thread.run_sync so the event loop stays responsive under load. Finally, retraining_flow() automates the full drift-check → retrain → evaluate → promote → hot-reload cycle as a schedulable Prefect deployment.
